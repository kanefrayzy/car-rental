# Backend notes

Laravel 13 API for the rental site. Read `README.md` in this folder first: endpoints, business rules and layout are there. The repo-wide notes are in `/CLAUDE.md`.

- This file replaces the Laravel skeleton's `AGENTS.md`/`CLAUDE.md`, which only told agents to install Laravel Boost. Boost is not installed and nobody asked for it.
- The API plus the owner's admin panel (Filament 5 at `/admin`, `app/Filament`). No Vite and no npm: Filament's compiled assets are published into `public/` by `php artisan filament:upgrade` (runs after `composer install`). Custom panel views (`resources/views/filament`) style themselves with a `<style>` block and Filament's CSS variables, because a Tailwind class Filament does not already use is not in its stylesheet.
- Booking rules for the owner's buttons (confirm, cancel, deposit received) are in `app/Services/BookingManager.php`; the panel only calls it. Keep it that way so the rules stay tested.
- Run `composer test` and `./vendor/bin/pint --test` after changes. Both pass as of 2026-10-21 (183 tests).
- Blog (2026-10-21): `App\Models\Post` keeps everything derived in its model events (slug, reading time, excerpt, old-slug redirects, deleting replaced covers, queuing `RevalidateBlog`), so the panel, tinker and tests behave the same. "Live" is `scopeLive()`: published and `published_at <= now`. Status and publish time are set by the editor's buttons (`Filament/Resources/Posts/Pages/ManagesPublishing.php`), not by form fields. The form's buttons sit in the page's `content` schema: test them with `TestAction::make('publish')->schemaComponent('form-actions', schema: 'content')`. Pictures go through `App\Services\BlogImages` only (GD, WebP); the name pattern `…_WxH.webp` and the copy widths are read by `frontend/lib/imageLoader.ts`: change both together. Do not touch `updated_at` when stamping `revalidated_at` (it is the post's "Updated" date on the site): use `toBase()->update()`.
- Status `returned` (2026-10-19): set by "Mark as returned" (`BookingManager::markReturned`, confirmed bookings only), which queues `App\Jobs\SendReviewRequest` `rental.review_delay_hours` (3) later. The job sends `App\Mail\ReviewRequest` once per booking: it claims `review_requested_at` with a conditional update before sending and clears it again if the send throws. Nothing is sent while `rental.review_url` (`GOOGLE_REVIEW_URL`) is empty. Returned bookings keep their dates, cannot be cancelled, take no documents (`isOpen()` is false), and can still be refunded and paid.
- Cancelling a card-paid booking refunds the amount the owner enters ("Amount to refund" in the cancel dialog, the full deposit by default, 0 keeps it all; user 2026-10-19): a late cancellation fee is kept from the deposit, as `/rental-terms` says. The cancellation email words a full refund, a partial one ("We refunded $X of your $1,000 deposit") and a kept deposit differently.
- Queue: `database` everywhere except tests (sync). A delayed job needs the worker (`queue` container, `APP_ROLE=queue`, which like the scheduler skips migrations in `docker/entrypoint.sh`). Nothing else is queued yet: every other email is sent inline with `Mail::send`.
- Request and response fields are camelCase to match `frontend/lib/api.ts`. Validation messages are shown to visitors as written and mirror `frontend/lib/validation.ts`; change both sides together.
- Money is whole US dollars in unsigned integer columns. Stripe amounts are converted to cents only inside `StripeDepositGateway`.
- Customer documents: private disk only, served only by `Api\BookingDocumentController` (behind the `signed` middleware, for the email links) and `Admin\BookingDocumentController` (inside the panel's authenticated routes). Keep `'serve' => false` on the `local` disk in `config/filesystems.php`. They are deleted after `rental.document_retention_days` by `bookings:prune-documents` (`app/Services/DocumentRetention.php`), run nightly by the scheduler.
- The site's server reads the daily price from `GET /api/cars` (`frontend/lib/catalog.ts`). Keep `pricePerDay` and `slug` in that response.
- `CarSeeder` uses `firstOrCreate` on purpose: the Docker entrypoint seeds on every start and must not undo a price changed in the database.
- Local dev server: `composer serve` (raises the upload limit), not `php artisan serve`. Its router is `dev-server.php`: it serves real files from `public/` (the admin panel's CSS and JS) and sends the rest to Laravel. Routing everything to `public/index.php` made the panel load unstyled.
- Writing PHP files through a shell heredoc failed here (quotes in the code); write them with the editor tools.
